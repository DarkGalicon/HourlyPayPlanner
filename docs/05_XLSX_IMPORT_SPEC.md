# 05. XLSX Import Specification (`nagr_xlsx_v1`)

## 1. Поддерживаемый формат

MVP поддерживает XLSX «Индивидуальный план преподавателя» текущего формата `nagr.stgau.ru`.

Sample-файлы показывают листы:

```text
Титульный
Summary
AutumnOch
SpringOch
Zaoch            # может отсутствовать
ЗаключениеКаф
```

Не требовать наличия `Zaoch`.

## 2. Определение формата

Перед импортом проверить сигнатуры:

- лист `Титульный`;
- лист `Summary`;
- хотя бы один из `AutumnOch` / `SpringOch`;
- на очных листах в шапке есть `Группа`, `Дисциплина`, `Лек`, `Пр`, `Лаб`, `Итого`.

Если структура не совпала — не угадывать, вернуть `UNRECOGNIZED_FORMAT`.

## 3. Титульный лист

В текущих sample-файлах присутствуют:

- строка вида `ФИО, тип занятости`;
- учебный год;
- кафедра;
- степень;
- звание;
- должность;
- `Ставок:`.

Парсер должен искать **по текстовым labels**, а не жестко полагаться только на одну координату. Допускается использовать известные координаты как fast path, но иметь validation.

Не использовать имя файла для определения преподавателя или типа занятости.

## 4. Summary

Использовать для контрольной сверки итогов, но не как единственный источник детализации.

В sample:

```text
Учебная работа → План очники / План заочники / Всего план
```

Поле `Факт` в sample равно нулю и для целей приложения не используется как источник фактической нагрузки.

## 5. AutumnOch / SpringOch

Текущая структура:

```text
A № строки
B Группа
C Курс
D Поток
E Студ.
F Факультет
G Дисциплина
H Лек
I Пр
J Лаб
K Контроль.Вид
L Контроль.Час
M Курсовые
N Дипломники
O ГАК и ГЭК
P Контрольные
Q РГР
R Практики
S Итого
T Факт
U Консультации экзамен
... Пояснения
```

Нельзя предполагать, что каждая Excel-строка содержит только один вид нагрузки. Нормализовать каждый заполненный часовой столбец в отдельный `WorkloadItem`.

### Mapping

```text
H → LECTURE
I → PRACTICE
J → LAB
K+L → CONTROL (control_type=K, hours=L)
M → COURSEWORK
N → THESIS
O → STATE_EXAM
P → CONTROL_WORK
Q → RGR
R → INTERNSHIP/PRACTICUM
U → EXAM_CONSULTATION (если заполнено)
```

Столбец `S Итого` хранить как `row_total_hours` для проверки, но не создавать из него дополнительный WorkloadItem, иначе часы задвоятся.
Если сумма H:R уже равна S, а U заполнен, часы U сохраняются отдельно как
`EXAM_CONSULTATION`, но не входят в расчётную нагрузку: это дополнительная
колонка вне итога строки. Показывать понятное информационное предупреждение.

### Пустые строки с потоком

В sample встречаются строки, где есть группа/поток, но нет часов. Не выбрасывать информацию о потоке бездумно. Для MVP:

- сохранять row metadata при необходимости;
- не создавать workload hours = 0;
- mapping потока можно использовать для отображения/связи групп.

## 6. Zaoch

Структура отличается.

В sample:

```text
A № строки
B Группа
C Курс
D Студентов
E Дисциплина
F:H Лек (Уст/Зим/Лет)
I:K Пр (Уст/Зим/Лет)
L:N Лаб (Уст/Зим/Лет)
O Вид контроля
P:R Контроль (Уст/Зима/Лето)
S:T дополнительные часы контроля по сезонам
U Курсовые
V Дипломники
W ГАК/ГЭК
X РГР
Y Практики
Z Итого
AA Факт
AB Консультации экзамен
```

Для заочки сохранить `session_period`:

```text
UST
WINTER
SUMMER
```

Поскольку бизнес-правило привязки заочных периодов к месяцам пока не подтверждено, **не назначать автоматически semester/month**. Они участвуют в общей нагрузке, но для почасового помесячного распределения пользователь должен подтвердить период/семестр.

## 7. Числа

В XLSX sample многие числа хранятся как строки (`"3.72"`, `"899.24"`). Использовать безопасный converter в `Decimal`.

Поддержать:

- точку;
- запятую;
- пробелы;
- пустое значение → None.

Не использовать `float`.

## 8. ИДПО

После чтения группы:

```python
is_idpo = normalized_group.startswith("ИДПО_")
```

## 9. Валидация итогов

После разбора файла:

- нумерованная строка с `Итого` учитывается даже тогда, когда ни один вид
  нагрузки в ней не заполнен;
- если `Итого` больше расшифрованных часов, сохранить разницу как
  `UNCLASSIFIED` (неаудиторные, недоступные для почасовки) и показать
  предупреждение с номером строки; не угадывать вид этих часов;
- сравнить учитываемую сумму нормализованных часов с планом в Summary отдельно
  по очной, заочной и общей нагрузке;
- несовпадение не должно тихо блокировать импорт, если файл читается; создать warning;
- при структурной ошибке — блокировать.

Версия правил чтения — `nagr_xlsx_v2`. Повторный импорт того же SHA-256 разрешён
только как обновление источника, который ранее был прочитан старой версией.
Старый источник остаётся в БД для сохранения связанных записей и должен быть
исключён пользователем из расчёта; включённый источник старой версии блокирует
расчёт с подсказкой о переимпорте.

## 10. Duplicate import

Вычислить SHA-256 исходного файла. Если такой `file_sha256` уже есть в БД, показать диалог:

```text
Этот файл уже импортирован.
[Отмена] [Импортировать повторно как новую версию]
```

По умолчанию — отмена.
