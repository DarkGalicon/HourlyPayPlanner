# 07. DOCX Export Specification

## Цель MVP

Заполнить в существующем шаблоне:

1. минимально необходимую шапку преподавателя;
2. таблицу занятий за выбранный месяц;
3. итог количества часов.

Остальные кадровые/финансовые поля и подписи остаются для ручного заполнения другими сотрудниками.

## Текущий шаблон

Содержит placeholders вида:

```text
{FIO}
{STEPEN}
{ZVANIE}
{DOLZNOST}
{BIRTH_DATE}
{ADDRESS}
{PASS_SERIAL}
{PASS_NUM}
{OTDEL}
{DATE_OTDEL}
{STRAX_NUM}
{INN_NUM}
{DATA}
{TIME}
{GROUP}
{DISCIPLINE}
{TYPE}
{HOURS}
{HOURS_SUM}
{DAY)      # в шаблоне опечатка
{MONTH}
{YEAR}
```

В базовом шаблоне исправить `{DAY)}` → `{DAY}` либо не использовать этот placeholder в MVP.

## Политика заполнения MVP

По умолчанию:

```text
FIO          → заполнить
STEPEN       → заполнить, если сохранено и включено настройкой
ZVANIE       → заполнить, если сохранено и включено настройкой
DOLZNOST     → заполнить, если сохранено и включено настройкой
```

После явного ввода в карточке преподавателя заполнять, если значение указано:

```text
BIRTH_DATE
ADDRESS
PASS_SERIAL
PASS_NUM
OTDEL
DATE_OTDEL
STRAX_NUM
INN_NUM
```

Даты выводятся в формате `ДД.ММ.ГГГГ`. Если значение отсутствует, placeholder
заменяется пустой строкой. Финансовые поля и подписи остаются для ручного
заполнения:

```text
стоимость часа
сумму
подписи
```

## Таблица занятий

Колонки шаблона:

```text
Дата
время проведения
группа
наименование дисциплины
вид занятий
кол-во часов
```

Для каждой `Lesson` создать отдельную строку.

```text
HOURS = 2
```

`HOURS_SUM` = сумма всех строк выбранного месяца.

## Mapping TYPE

Настраиваемый mapping:

```text
LECTURE  → "лекционные"
PRACTICE → "практические"
LAB      → "лабораторные"
```

Тексты должны быть в settings, чтобы их можно было изменить без правки кода.

## Формат даты/времени

Дата по умолчанию:

```text
DD.MM.YYYY
```

Время — точная строка time slot, например:

```text
08:30-10:05
```

Если шаблон требует перенос строки/другой separator, делать через exporter formatting, не менять domain.

В дате заявления `{MONTH}` заполняется названием месяца в родительном падеже
(например, «31 марта 2027 г.»), а даты занятий в таблице остаются в формате
`DD.MM.YYYY`. Между таблицей даты/подписи и таблицей «Количество часов» в
выходном документе должны быть два пустых абзаца (два Enter); исходный шаблон
при экспорте не изменяется.
Эти абзацы создаются без ссылок, полей и наследуемых служебных атрибутов, с
нулевыми отступами до/после. Перед блоком подписи не ставится принудительный
разрыв страницы: Word распределяет длинную таблицу по страницам естественно.
При семи и более занятиях текст строк занятий уменьшается до 10 pt, чтобы дата
и вид занятия не переносились внутри узких ячеек и не вытесняли подписи на
лишнюю страницу; оформление остальных частей шаблона не меняется.
Клонированные строки не наследуют идентификаторы абзацев Word, чтобы в DOCX
не появлялись повторяющиеся служебные ссылки на один и тот же абзац.
Дата заявления включена в интерфейсе по умолчанию; пользователь может снять
флажок, если хочет заполнить её вручную.

## Техническая реализация

Предпочтительный вариант:

- `docxtpl` для простых полей;
- `python-docx` для контролируемого клонирования/заполнения строк таблицы, если Jinja-row не сохраняет нужную верстку.

Exporter должен:

1. копировать template в новый документ;
2. не менять исходный template;
3. сохранять стили, ширины, границы и ориентацию;
4. подгонять строки так, чтобы документ не разваливался при нескольких занятиях;
5. генерировать безопасное имя файла.

Пример имени:

```text
Почасовка_Богданова_СВ_2026-10.docx
```

## Ограничение объема

Если строк настолько много, что форма уходит на несколько страниц, это допустимо только при сохранении читаемого заголовка таблицы. Конкретное требование к повтору header row проверить на реальном Word/LibreOffice и macOS Word.
