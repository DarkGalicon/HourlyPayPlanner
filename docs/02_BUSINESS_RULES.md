# 02. Business Rules

## 1. Норма и лимит почасовки

Базовая норма:

```text
Норма = эффективная_ставка × 900
```

Для целей этой программы плановые часы индивидуального плана используются как расчетные «фактические» часы.

```text
Расчетная_нагрузка = выбранные_фактические_часы − часы_ИДПО
Превышение = max(0, Расчетная_нагрузка − Норма)
```

Окончательный объем, который можно распределить как почасовку, дополнительно ограничен:

- 300 часами на сотрудника;
- доступным количеством допустимых аудиторных часов;
- ручным выбором пользователя.

Пользователь может явно разрешить превышение *расчётного* лимита при ручном выборе
нагрузки. Разрешение хранится для пары преподаватель/учебный год. Оно не отменяет
максимум 300 часов и ограничение доступных аудиторных часов каждой строки.

Важно: **эффективная ставка задается/подтверждается пользователем**. Не суммировать ставки всех файлов автоматически, потому что один преподаватель может иметь несколько видов занятости, и правило их агрегации зависит от рабочего контекста.

## 2. Источники нагрузки

Каждый импортированный XLSX создает `WorkloadSource`.

Для источника хранить:

- тип занятости из титульного листа;
- заявленную ставку;
- итог плановых часов;
- флаг `include_in_fact`;
- исходный файл / hash / дата импорта.

Пользователь может включить/исключить источник из расчета фактической нагрузки.
Импортированный источник можно удалить из базы после подтверждения, если его строки
не участвуют в сохранённом выборе нагрузки. Исходный XLSX на диске не удаляется.

Для экспорта годового распределения брать только сохранённые помесячные часы
выбранных аудиторных строк. Категория «бюджет/коммерция» в импорте отсутствует:
пользователь указывает её для каждой строки перед экспортом, программа не угадывает.

## 3. ИДПО

Признак:

```text
group_name.startswith("ИДПО_")
```

Все часы таких групп должны быть отдельно посчитаны и вычтены из расчетной фактической нагрузки, так как оплачиваются отдельно.

ИДПО не должно попадать в обычную почасовку второй раз.

## 4. Допустимые виды для почасовки

Разрешены только аудиторные занятия:

- `LECTURE` — лекции;
- `PRACTICE` — практические;
- `LAB` — лабораторные.

Контроль, экзамены, зачеты, курсовые, дипломники, ГАК/ГЭК, РГР, практики и прочие виды не попадают в почасовку автоматически.

## 5. Аномалии

Не считать любой неаудиторный вид «ошибкой». Он может быть нормальной частью нагрузки.

Отдельным предупреждением отмечать:

- неизвестный вид контроля, не входящий в конфигурируемый allowlist;
- неизвестный столбец/тип нагрузки;
- разницу между `Итого` строки и суммой распознанных составляющих выше tolerance;
- аудиторные часы с неожиданной дробностью;
- строку с непустыми часами, но без группы или дисциплины;
- несовместимую структуру листа.

В sample-файлах встречаются строки экзамена, где `Итого` больше явных часов контроля на 2 часа. Не объяснять это автоматически «консультацией», пока правило не подтверждено; показывать предупреждение о нерасшифрованной разнице.
Эта разница входит в общий план как `UNCLASSIFIED`, но не в доступные
аудиторные часы для почасовки. Консультации к экзамену, явно указанные вне
графы «Итого», сохраняются для аудита и не прибавляются к расчётной нагрузке.

## 6. Ручной выбор дисциплин

Программа **не выбирает** дисциплины/группы для почасовки автоматически.

Пользователь может выбирать:

- дисциплину;
- группу;
- вид занятия;
- часть доступных часов, а не обязательно все часы строки.

Выбранное количество должно быть неотрицательным, не превышать доступные часы и быть кратным 2.

## 7. Семестры и месяцы

Первый семестр:

- сентябрь;
- октябрь;
- ноябрь;
- декабрь.

Второй семестр:

- январь — опционально;
- февраль;
- март;
- апрель;
- май.

Почасовка распределяется только внутри соответствующего семестра, если пользователь явно не изменил семестровую принадлежность для особого случая.

## 8. Помесячное распределение

Для строки `дисциплина + группа + вид занятия`:

- каждый месяц содержит `0` или положительное целое число, кратное 2;
- сумма месяцев = выбранным для почасовки часам;
- значения не обязаны быть равномерными;
- допустимы, например, 4, 8, 10 часов в разных месяцах.

## 9. Печатное занятие

Одна строка в ежемесячном заявлении = **2 часа**.

Например:

```text
10 часов за октябрь = 5 строк занятий по 2 часа
```

## 10. Даты/время

- только Пн–Пт;
- исключить праздники и пользовательские нерабочие даты;
- учитывать ограничения доступности преподавателя;
- слот `дата + время` должен быть уникален для преподавателя;
- промежутки между занятиями в один день разрешены;
- жесткого требования последовательности слотов нет.

## 11. Начало семестра

В начале семестра есть разгоночный лекционный период. Пользователь задаёт одну
первую допустимую календарную дату практик и лабораторных на весь семестр учебного
года — общую для преподавателей, дисциплин и групп. До этой даты планируются только
лекции. Если дата не задана, генерация практик и лабораторных запрещена с явной
ошибкой; лекции можно генерировать. Дата не выводится автоматически из номера
учебной недели: практики могут начинаться со второй недели или позже.

Лекции могут проходить в любой допустимый день месяца. При наличии выбора генератор
предпочитает для них первые 14 календарных дней месяца; после этого срока они не
запрещены.

Занятие первого курса должно закончиться не позже 16:00. Ограничение действует
при генерации и ручном переносе. Для заочной формы генератор предпочитает слоты,
начинающиеся с 16:00; если таких слотов недостаточно, использует дневные.
Для очно-заочной нагрузки вечерний приоритет включается пользователем у выбранной
строки: текущий XLSX-импорт не выделяет эту форму отдельно. Ограничение первого
курса имеет приоритет над вечерним пожеланием.
